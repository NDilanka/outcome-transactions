# Exp 6 blind run: results

Generated by `research/exp6-executed/blind_results.py` from the private run files. Aggregates only.

## Scope

- 238 blind end states from 34 tasks (generator labels: 170 wrong, 68 correct). Labels below are the adjusted labels unless noted.
- Specs run as written (`specexec.py`). OSWorld checker run where its functions read a file.
- End states are the normalized copies: 15 workbooks were re-saved and recalculated by LibreOffice because the generator dropped cached formula values (`normalize_states.py`, checks in `normalize_report.json`). The unnormalized run is shown below for comparison.
- The primary result is the frozen run. A separate rerun with one executor fix is reported at the end and is not the primary result.
- The sample is below the 200-wrong-state gate (see Gates).

## Headline (primary run)

- Wrong accepts, all families: 2/173 (1.2%), after label corrections; 95% upper bound 4.11%. Labels as claimed: 3/170 (1.8%). If the a9f325aa formula state counts as wrong: 3/174 (1.7%).
- Commit rate on correct states in the LibreOffice families (group a): ACCEPT 15/33 (45.5%). REJECT 6/33 (18.2%). UNDECIDED 12/33 (36.4%).
- Wrong accepts in the LibreOffice families (group a): 2/86 (2.3%); 95% upper bound 8.15%.
- No-reader families (group b): ACCEPT is ruled out for all 119 states, because each has a predicate the executor cannot evaluate. Their 0 wrong accepts is not evidence about the specs.

## Cause of each non-accepted correct state in group (a)

18 of 33 correct group (a) states are not accepted. Each has one primary cause, assigned by reading the failing predicates and the request (`blind_private/causes.py`, private).

| cause | states | REJECT | UNDECIDED | tasks | meaning |
|---|---|---|---|---|---|
| executor defect | 8 | 2 | 6 | 0326d92d, 66399b0d, 6a33f9b9, 7ae48c60 | the executor has a bug or lacks a reader attribute the spec uses |
| prose/grammar | 6 | 0 | 6 | 550ce7e7, 88fe4b2d, 936321ce | a clause is written in prose, or in a form the spec grammar does not parse |
| contradiction | 1 | 1 | 0 | a9f325aa | two predicates of the same spec disagree about one state |
| spec over-pin | 1 | 1 | 0 | d53ff5ee | the spec demands more than the request asks for (the request is ambiguous) |
| renderer | 2 | 2 | 0 | ecc2413d | the page count depends on the renderer (LibreOffice here; Word was not available) |
| total | 18 | 6 | 12 | | |

Known executor defects, none fixed in the primary run:

- `table(n).rows` compared with an integer is tested row by row instead of counted. For a non-empty table, `rows == n` always fails and `rows != n` always passes. Fixed only in the rerun below.
- `.odt` files are opened with the .docx reader, which raises an error. The affected predicates stay UNDECIDED.
- Missing reader attributes: `CalcFile.charts`, `ShapeObj.height_cm` and `width_cm`, `TableObj.columns`, `DocxFile.body_order`.
- Grammar: quantifier forms such as `all x in ... where ...` and `all x in ...:`, `exists ... in ...:`, and clauses written as prose.
